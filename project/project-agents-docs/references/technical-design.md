# 技术设计文档规范

技术设计文档放在 `docs/technical/`，按主题或版本命名，例如 `docs/technical/{YYYY-MM-DD-主题-vN}.md`。内容必须基于代码、配置和已确认决策；不确定项标记“待补充”。

建议章节：背景、目标与非目标；技术栈选择（前端、后端、数据库、缓存、消息、部署基础设施，含版本与理由）；项目结构（目录、模块职责、依赖方向、数据流）；数据模型（实体/表、字段、类型、主键索引、关系、生命周期、迁移兼容）；关键技术点（并发、一致性、幂等、事务、性能、安全、容错、可观测性）；核心流程/时序；配置、部署、回滚与运维影响；风险、取舍和待决策事项。

需求驱动的设计应从需求 `PLAN.md` 链接；设计变更同步 CHANGELOG 或版本历史。
